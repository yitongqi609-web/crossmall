# CrossMall · 潮汐全球购 🌊

> 跨境电商独立站(B2C)—— 多币种结算 / 关税试算 / 国际物流 / 履约状态机 / 支付幂等
>
> Java 21 · Spring Boot 3.5 · MyBatis-Plus · MySQL 8.4 · Redis 7.4 · RocketMQ 5.3 · Vue 3 · Element Plus

## 一、项目简介

CrossMall 是一个面向海外消费者的跨境电商独立站,完整覆盖 **逛 → 加购 → 结算(运费+关税试算)→ 下单(汇率快照)→ 支付(幂等回调)→ 国际履约(状态机+轨迹)→ 妥投** 全链路,并配套管理端(商品/汇率/税则/物流线路/订单履约/数据看板)。

与普通商城相比,跨境场景独有的技术挑战——**多币种金额一致性、汇率波动、目的国关税、国际物流计费、长链路履约追踪**——是本项目的设计重心。

## 二、六大核心设计(面试考点)

| # | 考点 | 方案 | 权衡与理由 |
|---|------|------|-----------|
| 1 | **多币种与汇率快照** | SKU 只存基准币(USD 分);展示价由汇率服务实时换算;**下单瞬间把汇率写入订单快照**,支付/退款全部按快照金额 | 与实时汇率解耦,杜绝"下单到支付间汇率波动导致金额不一致";内部统一 USD 分(BIGINT)规避浮点精度 |
| 2 | **关税与运费试算** | 税则表 (国家×HS编码) 三级匹配:国家+HS → 国家默认`*` → 全球默认;de minimis 免税额度(美 $800 / 澳 AUD1000);运费按首重/续重计费,整单计费重=Σ(件重×数量) | 关税在**下单前试算、下单时固化**进订单三段金额(商品/运费/关税),价格透明是跨境独立站转化率关键 |
| 3 | **履约状态机** | 枚举 + 合法流转表(`TRANSITIONS`)是唯一真相源;流转 = 状态机校验 + `WHERE status=期望值` 条件更新双保险 | 非法跳状态(如 DECLARED→COMPLETED)直接拒绝;并发下条件更新失败视为过期请求,天然解决"管理端双开_tab 重复操作" |
| 4 | **支付幂等** | 三道防线:① 回调验签 MD5(txnNo\|amount\|secret) ② Redis SETNX 防重闸门 ③ 流水条件更新 INIT→SUCCESS(txn_no 唯一索引兜底);金额不一致直接拒绝(防篡改) | 真实网关必会重试回调;幂等是支付第一原则。回调用「结果对象」而非异常返回业务失败,避免误回滚已落库状态 |
| 5 | **超时关单** | 下单事务提交后(afterCommit)发 RocketMQ **延迟消息**;消费者条件更新 PENDING_PAYMENT→CANCELLED 并双端回补库存;另有定时**兜底对账**扫描过期单 | afterCommit 发消息避免"消息先于订单落库被消费";延迟等级向上取整保证消息不早到;支付与关单赛跑由条件更新裁决,输方自动补偿 |
| 6 | **库存防超卖** | 三层:Redis Lua 原子预扣(判存+扣减一体,挡量)→ DB `WHERE stock>=n` 条件更新(权威兜底)→ 取消/关单/退款双端回补 | Redis 只做"闸门"不是账本;任何一步失败都有对应的回补路径,冒烟测试验证 30 并发下单后库存分毫不差 |

**辅助亮点**:商品多语言(字段成对返回,前端按 locale 取用)、汇率 Redis 读穿透缓存 + 内存币种表、MQ 异步落履约轨迹(主链路不因轨迹写放大变慢)、 Knife4j 全接口文档。

## 三、功能清单

**用户端(中/英双语,6 币种切换)**
- 首页聚合 / 分类浏览 / 关键词搜索 / 商品详情(SKU 规格、多币种价格)
- 购物车(Redis,实时解析价格与库存)

- 模拟收银台(PayPal / 国际卡,倒计时支付)
- 订单列表 / 详情(履约轨迹时间线)/ 待付款取消
- 个人中心:国际地址簿管理

**管理端**
- 数据看板:GMV(USD 折算)/ 有效订单 / 近 7 日趋势 / 状态分布 / 热销 Top5(ECharts)
- 商品管理:SPU+SKU 整体编辑(双语内容、HS 编码、库存)、上下架
- 分类管理 / 汇率管理(手动改 + 模拟第三方拉取)/ 关税税则(国家×HS,免税额度)/ 物流线路(首重续重、目的国)
- 订单履约:按状态筛选 → 详情抽屉 → 依据状态机的下一步流转按钮(备货→报关→干线→清关→派送→妥投 / 发货前退款)+ 轨迹时间线 + 关单兜底对账

## 六、核心链路时序

```
下单   preview(运费+关税+汇率试算)
       → Redis Lua 预扣(失败快速返回)
       → DB 条件扣减 stock>=n(失败回补 Redis 并回滚)
       → 订单落库(汇率/金额/地址三快照)
       → afterCommit 发延迟关单消息

支付   收银台发起 → 创建支付流水 INIT(金额=订单快照)
       → 网关签名回调 → 验签 → Redis SETNX → 流水条件更新 INIT→SUCCESS
       → 订单条件更新 PENDING_PAYMENT→PAID(失败:关单赛跑输方,流水置 VOID)
       → afterCommit 发 PAID 轨迹消息

履约   管理端流转 → 状态机合法流转表校验
       → 条件更新 WHERE status=期望值
       → MQ 异步写轨迹节点(仓库/报关/干线/清关/派送/妥投)

关单   延迟消息到点 → 仍待付款且已超时 → 条件更新→CANCELLED
       → 双端回补库存(DB+Redis)→ 写 CANCELLED 轨迹
       (MQ 消息丢失由管理端「兜底对账」与定时扫描托底)
```
